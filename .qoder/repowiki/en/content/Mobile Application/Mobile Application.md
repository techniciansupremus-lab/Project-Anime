## Introduction
This document explains the mobile application for Project Anime built with Capacitor, which wraps a React web app into a native Android application. The application leverages Capacitor 8.x framework to bridge the web layer with native Android capabilities, providing seamless integration between the React frontend and Android system features. It covers the complete setup including Capacitor configuration, native Android project structure, build and signing procedures, mobile-specific features such as touch interactions and device capability detection, testing and debugging guidance, and performance considerations for streaming media on Android devices.

## Architecture Overview
Capacitor acts as a bridge between the React web app and native Android. The web app runs in a WebView managed by BridgeActivity, with plugins registered and invoked from JavaScript to access native features like status bar control, splash screen management, deep links, and file storage. The architecture supports modern Android development practices with Java 21 compatibility and AndroidX libraries.

## Performance Considerations
- **Streaming Media**:
  - Use hardware-accelerated playback where possible and ensure HLS support via hls.js in the web layer.
  - Keep WebView cache size reasonable; avoid excessive DOM nodes during playback.
  - Leverage Android's native video decoding capabilities through WebView optimizations.
- **Memory Management**:
  - Minimize long-lived references in JS; release event listeners when navigating away.
  - Avoid heavy image processing on the UI thread; prefer background tasks or native libraries when necessary.
  - Monitor WebView memory usage and implement proper cleanup strategies.
- **Network and I/O**:
  - Enable HTTP caching at the server level; leverage CDN for static assets.
  - Use compression (gzip/brotli) for responses to reduce bandwidth usage.
  - Implement proper error handling for network failures in streaming scenarios.
- **UI Responsiveness**:
  - Offload heavy computations to Web Workers to maintain smooth scrolling and interactions.
  - Debounce resize/orientation handlers; use the provided useDeviceType hook to update UI efficiently.
  - Optimize rendering performance by minimizing layout thrashing.
- **Battery Optimization**:
  - Pause media when app moves to background using the appStateChange listener.
  - Reduce polling frequency while in background to conserve battery life.
  - Implement proper resource cleanup when transitioning between foreground and background states.

## Troubleshooting Guide
- **Build Issues**:
  - Verify SDK path in local.properties and that AndroidX is enabled in gradle.properties.
  - Clean and rebuild if dependency resolution fails; clear Gradle cache if needed.
  - Ensure Java 21 compatibility for Capacitor 8.x requirements.
- **Runtime Errors**:
  - Check logs via adb logcat for exceptions thrown by plugins or WebView.
  - Ensure INTERNET permission is present in the manifest for streaming functionality.
  - Verify plugin initialization order and proper error handling in nativeApp.js.
- **Splash/Status Bar**:
  - If splash does not hide, verify initialization order in nativeApp.js and that the correct resource name is set in capacitor.config.json.
  - Check theme configurations in styles.xml for proper splash screen display.
- **Deep Links**:
  - Confirm the custom URL scheme matches strings.xml and that the appUrlOpen listener is registered.
  - Test deep link handling across different Android versions and device configurations.
- **ProGuard**:
  - If crashes occur after enabling minification, add keep rules for any custom JS interfaces or third-party libraries.
  - Review proguard-rules.pro for necessary exclusions and debugging information preservation.
