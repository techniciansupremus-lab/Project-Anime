## Overview

The EetNet monorepo builds three artifacts from a single source tree:
- A React/Vite web application (SPA)
- An Express.js API server (`server.js`) that proxies anime/manga/drama streams and metadata
- A Capacitor Android native shell that wraps the built SPA into an APK

There is no Makefile, Dockerfile, or CI pipeline in the repository. Build orchestration lives entirely in `package.json` scripts, Vite configuration, Gradle build files, and a Vercel deployment manifest.

## Frontend build (Vite)

- **Toolchain**: Vite 8 with `@vitejs/plugin-react`. The project uses ES modules (`"type": "module"`).
- **Entry**: `index.html` → `src/main.jsx`.
- **Scripts** (`package.json`):
  - `npm run dev` — starts the Vite dev server (port defaults to 5173).
  - `npm run build` — runs `vite build`, emitting static assets to `dist/`.
  - `npm run preview` — serves the production build locally.
  - `npm run lint` — runs `oxlint` (configured via `.oxlintrc.json`).
- **Dev proxy** (`vite.config.js`): forwards `/anilist-proxy` to `https://graphql.anilist.co` and `/api` to `http://localhost:8080` so the frontend can call the backend without CORS issues during development.
- **Linting**: OxLint is the only linter; there is no formatter configured at the repo root.

## Backend build (Node/Express)

- **Runtime**: Node.js with ESM imports (`import ... from ...`).
- **Entrypoint**: `server.js` — a single-file Express app exposing `/api/*` routes for image proxying, HLS/M3U8 rewriting, subtitle proxying, episode metadata, and provider scrapers.
- **Startup**: `npm run start` / `npm run server` both execute `node server.js`. The port is read from `process.env.PORT` (default 8080).
- **Configuration**: All external endpoints are environment-driven (`KISSKH_BASE`, `ENCDEC_BASE`, `HIVETOONS_BASE`, `CORS_ORIGIN`, `ANIMERULZ_*` URLs). No config file is checked in.
- **Serverless support**: `server.js` normalizes non-`/api` URLs to `/api/...` so it works behind Vercel's edge router; `vercel.json` rewrites `/api/(.*)` to `/api/index.js` and `/api/runtime-config` to `/api/runtime-config.js`.

## Android build (Capacitor + Gradle)

- **Wrapper**: `capacitor.config.json` declares `appId: com.eetnet.app`, `appName: EetNet`, and `webDir: dist` — meaning the Capacitor Android build consumes the output of `npm run build`.
- **Gradle structure**:
  - Root `android/build.gradle` applies `variables.gradle` and registers Google/Maven Central repos.
  - `android/app/build.gradle` defines the Android application module: `compileSdk = 36`, `minSdkVersion = 24`, `targetSdkVersion = 36`, `versionCode 1`, `versionName "1.0"`. Release builds apply ProGuard rules but do not enable minification by default (`minifyEnabled false`).
  - `android/variables.gradle` centralises dependency versions (AndroidX, Cordova, JUnit, Espresso).
  - `android/app/capacitor.build.gradle` is auto-generated by Capacitor and pins Java 21 source/target compatibility; it pulls in Capacitor plugin projects (`capacitor-app`, `capacitor-browser`, `capacitor-filesystem`, `capacitor-preferences`, `capacitor-splash-screen`, `capacitor-status-bar`).
- **Build commands** (standard Capacitor flow):
  1. `npm run build` — produces `dist/`.
  2. `npx cap sync` — copies `dist/` into `android/app/src/main/assets/public/`.
  3. `cd android && ./gradlew assembleDebug` / `assembleRelease` — builds the APK/AAB.
- **ProGuard**: `proguard-rules.pro` exists under `android/app/`; release builds reference it but shrinking is disabled.
- **Google Services**: The app conditionally applies `com.google.gms.google-services` if `google-services.json` is present (push notifications path).

## Deployment

- **Vercel**: `vercel.json` configures:
  - Cache-Control headers on `/` and `/index.html` set to `no-cache, no-store, must-revalidate`.
  - Rewrites: `/api/runtime-config` → `/api/runtime-config.js`, all other `/api/*` → `/api/index.js`, and any non-asset path falls back to `/index.html` (SPA routing).
- **Local dev**: `npm run dev` runs the Vite dev server which proxies `/api` to the local `server.js` process running on port 8080.

## Conventions & constraints observed

- **Single-package monorepo**: All dependencies (frontend, backend, Capacitor plugins) are declared in one `package.json`; there are no workspaces or sub-packages.
- **Environment variables drive runtime behavior**: Provider bases, CORS origin, and fallback endpoints are loaded from `process.env` at startup — no config files are committed.
- **WebDir convention**: The Capacitor Android build expects the SPA under `dist/` (set in `capacitor.config.json`), so `npm run build` must be run before `capacitor sync`.
- **API surface is versioned implicitly by route prefix**: All backend endpoints live under `/api/*`; the server rewrites bare paths to this prefix for Vercel compatibility.
- **No containerization**: There are no Dockerfiles or docker-compose files in the repository.
- **No CI/CD pipeline**: No GitHub Actions, GitLab CI, or similar configuration was found; deployment appears manual or managed outside this repo.
